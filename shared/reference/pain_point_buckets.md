# 用户痛点桶 — 真实评论提取规则

> `xhs-viral-pulse` 在 §三·3.2 用这套桶把真实评论分类。`xhs-account-decompose` 在 §三 audience 分析里用类似规则。
>
> **关键原则**：每条痛点必须是**真实评论原文 + IP + 赞数 + 出处**，不是反推或泛化。

---

## 8 个痛点桶（默认配置）

按"评论密度 × 总赞数"排序，每桶取赞数 TOP 4 评论。

### 1. 反复内耗 / 想太多

**触发关键词**：`["内耗", "想太多", "反刍", "纠结", "犹豫", "焦虑"]`

**心理画像**：用户在事情发生后反复琢磨、自我攻击、走不出来。

**典型评论模式**：「我每件小事都要想 N 遍」「明明知道没必要，还是停不下来」

---

### 2. 不被理解 / 孤独

**触发关键词**：`["没人懂", "理解", "孤独", "一个人", "陪我", "倾诉", "说话"]`

**心理画像**：身边没有可深度倾诉的人；社交活跃但内心孤岛。

**典型评论模式**：「在小城没人能聊」「家人不懂」「朋友都活得很顺」

---

### 3. 自我否定 / 配不上

**触发关键词**：`["配不上", "不配", "自卑", "没用", "差劲", "废物", "没能力"]`

**心理画像**：核心信念里"我不够好"，对成功有抗拒。

**典型评论模式**：「即使做到了也觉得是运气」「其他人比我强多了」

---

### 4. 关系受伤 / 情感

**触发关键词**：`["出轨", "分手", "前任", "婆婆", "妈妈", "爸爸", "老公", "老婆", "男朋友", "女朋友", "前夫"]`

**心理画像**：当下处在或刚刚走出关系痛苦中。

**典型评论模式**：「最近发现他出轨了」「跟妈妈又吵架」「分手三个月还是放不下」

---

### 5. 工作 / 经济压力

**触发关键词**：`["工作", "上班", "失业", "钱", "房贷", "穷", "辞职", "卷", "加班"]`

**心理画像**：经济焦虑 + 职业迷茫双重叠加。

**典型评论模式**：「找工作好难」「房贷压得喘不过气」「想辞职但不敢」

---

### 6. 无力感 / 想躺平

**触发关键词**：`["躺平", "没动力", "起不来", "无力", "崩溃", "撑不下去", "想死", "活着"]`

**心理画像**：能量低谷，感觉付出和回报失衡，质疑活着的意义。

**典型评论模式**：「最近什么都不想做」「活着好累」「真的撑不下去」

---

### 7. 情绪化 / 易哭

**触发关键词**：`["想哭", "眼泪", "破防", "瞬间", "戳中", "看哭"]`

**心理画像**：情绪表面化，被特定金句或场景秒泪。

**典型评论模式**：「看到这一句直接哭出来」「这条戳到我了」

---

### 8. 被治愈 / 共鸣

**触发关键词**：`["治愈", "救了我", "刚好", "需要", "及时", "感谢", "谢谢"]`

**心理画像**：寻求情绪 validation，"我不是一个人"的需求。

**典型评论模式**：「正好今天需要看到这个」「谢谢你写下这些」

---

## 桶可定制（per niche）

`shared/lib/analyze.py::PAIN_BUCKETS` 是 list of (label, keywords)。用户可以：

- 加新桶（如「学业焦虑」`["考试", "成绩", "毕业", "内卷"]`）
- 改关键词（增减）
- 改桶顺序（影响排序）

---

## 抽取流程

```python
for note in all_notes:
    for comment in note.top_comments:
        content = comment.content
        if len(content) < 10: continue  # 跳过过短评论
        bucket = match_bucket(content)  # 命中第一个 bucket
        if bucket:
            pain_quotes[bucket].append({
                "quote": content,
                "likes": comment.likeCount,
                "ip": comment.ipLocation,
                "from_note": note.title,
                "note_likes": note.likes,
            })

# 每桶按 likes desc 取 TOP 4
for bucket in pain_quotes:
    pain_quotes[bucket].sort(key=lambda x: x["likes"], reverse=True)
    pain_quotes[bucket] = pain_quotes[bucket][:4]
```

## 痛点 → 选题映射模式

`xhs-viral-pulse` §三·3.2 末尾会自动生成"痛点 → 选题映射"段落。模板：

> - 「<高密度桶>」是评论密度最大的桶 → 这就是为什么「<对应关键词>」是稳定流量词
> - 「<不被理解桶>」里大量 IP 显示<地域规律> → 暗示<结构性需求>
> - 「<被治愈桶>」反映：用户不需要解决方案，只要「<情绪需求>」

---

## 不要做的事

- ❌ 不要"反推"痛点（看标题猜评论会说什么）
- ❌ 不要泛化到"人类普遍痛点"层面（要保留 IP + 赞数 + 出处粒度）
- ❌ 不要为了配平把空桶填满（空桶就是空桶——是有意义的负面信号）
